# DisciplineOS GitHub 发布检查

本文档用于记录当前版本的完成范围、未完成范围、项目介绍草稿，以及上传 GitHub 前必须排除的隐私文件。

## 项目介绍

DisciplineOS 是一个本地优先的个人投资纪律系统。它不负责荐股、预测价格或替用户交易，而是把投资者事前定义的纪律规则、证据要求、仓位上限、复盘流程和违规记录串成一个可执行、可审计、可复盘的工作台。

系统的核心目标是回答一个问题：这次交易是否符合我事先写下的纪律，而不是这次交易一定会不会赚钱。

当前版本包含 Python 后端、命令行工具和本地 Web UI。用户可以创建纪律卡、维护投资者画像和持仓簿，在交易前通过决策闸门审查买入、加仓、减仓、清仓等动作；系统会记录规则结果、违规台账、证据项、月度复盘和信息解读结果。可选 AI 层只用于材料解读和纪律建议辅助，不应被视为投资建议或自动交易依据。

## 当前已完成

- 本地 Web UI 和 CLI 启动入口。
- 中英文 UI 切换，中文模式覆盖主要页面、按钮、弹窗和表单文案。
- 纪律卡生成器：支持模板、常见 A 股/港美股代码补全、仓位上限、必须减仓、提高/降低仓位上限条件。
- 投资者画像：支持账户名称、风格占比、全局仓位约束、财报前加仓约束、行为弱点词库。
- 持仓簿：支持资产类型、市场、行业、主题、币种等常见下拉建议。
- 决策闸门：按纪律卡、证据、情绪状态、仓位变化和交易动作生成审查结果。
- 规则引擎：覆盖单票仓位、证据缺失、情绪化补仓、财报前加仓、FOMO、报复性交易、逻辑漂移、风格漂移、估值约束和复盘要求。
- 证据引擎：支持手动证据、从已保存纪律卡选择标的、证据库弹窗查看。
- 信息解读中心：支持 PDF/文本路径选择、本地规则解读、可选 OpenAI-compatible AI 解读、把解读结果转为证据或纪律卡建议。
- 数据源中心：支持 QMT、TuShare、AkShare、CSV、Excel、本地手动数据源的配置 UI、能力选择、个股代码过滤、同步日志弹窗。
- CSV/Excel 导入：已支持持仓、交易流水、日 K、5 分钟 K、成交量和财务指标等结构化表格转证据。
- 仓位护栏：计算单标的、行业、主题、市场、币种暴露并给出警告。
- 月度复盘：生成纪律评分、违规统计、归因、规则修订建议、报告快照。
- 纪律卡库、违规台账、决策历史、交易流水、副驾驶、数据源日志、系统状态等已从主页收纳到按钮/弹窗，降低主页拥挤度。
- 本地备份和恢复入口。
- 测试覆盖主要后端模块。

## 当前未完成或仍是原型

- QMT 真实数据连接器未实现，目前只保存本地路径并给出明确状态。
- TuShare 真实远程拉取未实现，目前只保存 Token 并校验配置状态。
- AkShare 真实拉取未完整接入，目前仍是数据源配置和状态框架。
- AI 在线搜索不是应用内置搜索；当前只是在启用 AI 时把需求交给配置的模型处理。
- DOC/DOCX 文档解析还不完整，PDF 解析相对更可靠。
- 没有用户登录、权限管理、加密存储和多用户隔离，当前定位仍是本地单人使用工具。
- 市场行情和财务指标还没有形成完整时序数据库、图表系统和自动增量更新流程。
- UI 自动化/E2E 测试还未补齐。
- 尚未配置 GitHub Actions、发布包构建流程和正式 release 工程。
- 示例数据需要单独准备公开版本，不能直接使用本机 `data/` 目录。

## 不应上传的内容

以下内容包含本地运行数据、路径、数据库、缓存或环境信息，必须排除：

- `data/`
- `data/disciplineos.db`
- `data/*.json`
- `data/reports/`
- `data/backups/`
- `.venv/`
- `.pytest_cache/`
- `__pycache__/`
- `src/disciplineos.egg-info/`
- `.env` 和 `.env.*`
- `*.db`、`*.sqlite`、`*.sqlite3`
- `*.zip`

当前扫描已经发现 `data/` 中包含本地 QMT 路径、桌面 PDF 路径、真实纪律卡、真实分析记录和设置项，因此不能公开上传。

## 上传前检查命令

```powershell
.\.venv\Scripts\pytest.exe -q
.\.venv\Scripts\python.exe -m compileall -q .\src
```

如果本机已安装 Git，可以先检查待上传文件：

```powershell
git status --short
git check-ignore -v data\disciplineos.db .venv\pyvenv.cfg
```

确认 `data/` 和 `.venv/` 已被忽略后再提交。
